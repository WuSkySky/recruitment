# Recruitment Simulation · 招新仿真比赛

**AzureSky 机器人战队 · 基于 ROS 2 与 Gazebo Classic 的多机器人仿真对抗平台**

> 项目方提供场地、机器人、基础控制、裁判系统与比赛终端；参赛者在这一基础设施之上实现感知、
> 定位、导航与决策，在统一、可复现的对抗环境中完成比赛任务。

---

## 1. 项目定位

RoboMaster 一类的机器人比赛，单台机器人同时需要机械结构、嵌入式系统、运动控制、
视觉识别、感知与导航，整支队伍还要做资源分配和战术决策。想要在招新阶段考察这些能力，直接
上真车成本高、可重复性差、风险也大。

本项目把赛场搬进仿真：完整的 RMUL 2026 3V3 场地、两台不同兵种的机器人、可用的底盘/云台/
射击、以及一套裁判系统。参赛者拿到的是一个"能打"的环境，需要自己
设计与实现的是让机器人打得好的那部分——**自瞄、感知、定位、导航、决策与整机联调**。

## 2. 比赛速览

完整的场地尺寸、机器人参数、比赛流程与判罚细则见 [doc/rules.md](docs/rules.md)

| 项目 | 设定 |
| --- | --- |
| 场地 | RMUL 2026 3V3，含启动/补给区与中央控制区 |
| 阵容 | 红蓝双方各一台步兵、一台哨兵，共四台机器人 |
| 时长 | 180 秒 |
| 初始胜利点 | 双方各 200 点 |
| 中央控制区 | 3 × 3 m，先到先得，离区保留 2 秒，占领每秒扣对方 1 点 |
| 战亡与复活 | 战亡扣 20 胜利点；读条复活（首次 5 秒，每次 +5），复活后 20% 血量、无敌 30 秒且虚弱（锁枪、不能占点） |
| 回血 | 占领己方补给区每秒恢复 25% 上限血量；进己方补给区同时解除虚弱与无敌 |
| 胜负判定 | 一方胜利点归零即结束；时间耗尽后依次比较胜利点 → 全队攻击伤害 → 总剩余血量，仍相同则平局 |

## 3. 平台能力

详细见 [doc/uesr_guide.md](docs/uesr_guide.md)

| 领域 | 已提供 |
| --- | --- |
| 机器人 | `pb2025_infantry_robot`、`pb2025_sentry_robot` 完整模型：装甲、灯条、麦轮底盘、云台、发射机构 |
| 基础控制 | 底盘速度、云台速度控制与角度/角速度反馈、射击开关、灯条改色、真值里程计 |
| 传感器 | 步兵：工业相机；哨兵：工业相机 + Mid360 点云 + 云台 IMU |
| 裁判系统 | 血量、17 mm 射击热量与过热锁枪、装甲命中判定、整机/分支失能、战亡扣点、读条复活与无敌/虚弱、补给区回血、比赛状态机、胜利点与中央占点 |
| 比赛终端 | 浏览器选手端（第一视角 + 原始键鼠输入）与裁判端，无需安装客户端 |

## 4. 环境要求

Ubuntu 22.04 + ROS 2 Humble + Gazebo Classic 11.10.2

## 5. 快速开始

详细见 [uesr_guide.md](docs/uesr_guide.md)。

```bash
# 1. 构建
colcon build
source install/setup.bash

# 2. 启动
ros2 launch recruitment_sim_bringup bringup.launch.py
```

启动后浏览器访问 `http://<仿真主机地址>:8080`，在选择页可分别打开红方选手端、蓝方选手端和裁判端。
